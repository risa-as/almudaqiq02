## High — money & stock integrity (fixed, each covered by a test)

- **POS sale** (`/api/transactions`): total recomputed server-side (tampered totals refused); qty must be > 0 (negative qty used to add stock and pay out cash); units must belong to the line's product; stock checked against **the branch's batches** (was global `baseStock` → a branch could sell another branch's stock); concurrent sales: batches re-planned under `FOR UPDATE` + guarded decrement (no oversell, no false refusals); receipt numbers unique under concurrency (per-tenant advisory lock); unpaid portion requires a customer and is booked for SPLIT sales too; cashier `branchId` spoof ignored.
- **Refund / return**: amounts and costs come from the original sale lines (client price was trusted → arbitrary cash-out); capped at what is still refundable; serialized per invoice (concurrent double refund impossible); goods restocked into **branch batches** (return only bumped `baseStock` → unsellable); credit sales cancel debt first and only the rest is cash; return COGS now reversed in profit; staff can only refund their own branch's sales.
- **Shift close**: summary and close used different formulas (SPLIT cash, returns) → one shared formula (`lib/shift-cash.ts`).
- **Transfers**: no state machine (PENDING→COMPLETED skipped stock; COMPLETED→APPROVED→COMPLETED moved stock twice); unit conversion ignored (1 carton moved as 1 piece); shortages silently dropped. All fixed + atomic claim.
- **PO receive / stocktake complete**: double-submit booked stock and supplier debt twice; stocktake committed per item. Both now claim atomically in one transaction.
- **Stock-in**: an owner's stock landed in their token branch, not the selected one; unit/supplier not tenant-checked.
- **Product create**: web never sent the selected branch (initial stock always went to the first branch).
- **Supplier PUT** wrote `balance` directly (ledger divergence) → removed; adjust-balance manager-only.
- Offline (desktop) refunds/returns and customer balances now mirror to the cloud.
- Clients updated for the new refund semantics: web POS and mobile show the **server's** amount — "أعد للعميل
  نقداً: X" plus the debt reduced (credit invoices) — instead of the client estimate.
- Transfer approval is the **source branch's** (or an owner's) decision; the receiving branch can only reject.
  The Approve button is hidden accordingly on web `/transfers` and mobile approvals.

## High — authorization & isolation (fixed)

- One role-aware helper `lib/branch-scope.ts`; ~35 routes that read `branchId` from the query/body now pin branch-bound roles (cashier, stock keeper, branch manager) to their token branch and validate owners' choices against the tenant (Prisma `connect` accepts foreign ids).
- Offers: cashiers could create/modify discounts → managers only; value/type validated; product/category tenant-checked.
- Customers: cashiers could delete customers (wiping debt) or set credit limits/opening balances → managers only.
- Users: branch managers could edit/reset passwords of other branches' staff → blocked; invalid roles rejected; password/role change revokes refresh tokens.
- Branches: writes owner-only.
- Super-admin API: in-route guard on all 12 route files (not middleware only).
- Audit log: rows without tenantId were shown to **every** tenant, and customer/product edits were logged without tenantId → fixed both.
- Electron `backup:save` IPC: path traversal → filename sanitized.
- Import: 5 MB / 5000-row caps.

## Remaining / user actions before deploy (cannot be done from code)

1. **Rotate every secret** that was in `.env` (C1) — `node scripts/generate-secrets.js` prints fresh JWT/refresh/branch/cron secrets and a new Ed25519 license key pair (terminal only, nothing written to disk); paste them into Vercel → Settings → Environment Variables and your local `.env`, then redeploy. Effects: new JWT/refresh secrets sign everyone out; a new BRANCH_TOKEN_SECRET means desktops re-activate; a new **LICENSE_PRIVATE_KEY** means re-issuing offline licenses and shipping the new public key. Rotate by hand in their own dashboards: the **Neon DB password** (→ DATABASE_URL) and the **Gemini/OpenAI keys**. Mandatory if the Jul-29 installer was given to anyone.
2. **Distribute only the new installer** (rebuilt 2026-10-08, verified — see 8). Treat any copy of the Jul-29 installer as compromised.
3. Purge `backups/*.db`, `dump.txt` from git history (`git filter-repo`) if the GitHub repo was ever shared/public.
4. Vercel: set CRON_SECRET (crons fail closed without it), optionally UPSTASH_REDIS_REST_URL/TOKEN (rate limits are per-instance otherwise); keep Function Region = Frankfurt in the dashboard.
5. Deploy, then verify: `curl -sI https://app.faramace.com/api/cron/daily-digest | grep -i x-vercel-id` → second code `fra1`, status 401 (not 404).
6. Mobile: release builds via EAS profiles (`https://app.faramace.com`); `mobile/.env` points to a LAN dev IP for local runs only.
7. Desktop-originated ADMIN accounts / admin password changes no longer sync to the cloud by design — manage owners on the web.

8. **Free disk space on C:** — only 0.38 GB was free and the first NSIS run aborted (`can't write 67108864 bytes`).
   After freeing my test artifacts the installer was rebuilt successfully: `dist/المدقق Setup 0.1.0.exe`
   (2026-10-08 10:30, 412 MB), afterPack gate passed; app.asar = `electron/`, icons, `package.json` only;
   `resources/server/.env` has no secrets; `dev.db` is the zero-row shipping DB. The old leaky installer is gone.
   This installer ships no secret, so rotating the cloud secrets does not require rebuilding it (desktops must
   re-activate after BRANCH_TOKEN_SECRET changes). Rotating LICENSE_PRIVATE_KEY does require shipping the new
   public key in the offline-desktop app (separate repo) and re-issuing its licenses.
